# Проектирование сервиса (этап 0)

## 1. Карточка сервиса

| Поле | Значение |
|---|---|
| Наименование | Сервис видеоконференций plugNmeet |
| Вариант задания | 3 — plugNmeet |
| Назначение | Онлайн-занятия и совещания для преподавателей и студентов домена gerber.org: видео и звук, демонстрация экрана, чат, общая доска, обмен файлами, запись |
| Пользователи | Группы домена: Admins, Teachers — модераторы комнат; Students — участники |
| Адреса | https://meet.gerber.org — веб-клиент и API; https://livekit.gerber.org — медиасервер |

| Клиентский хост | WIN-CL1.gerber.org (192.168.122.20), Windows 10 Pro |
| Домен | gerber.org — Samba AD DC на srv-1 |
| Способ развёртывания | Нативная установка без контейнеров, службы systemd |
| Владелец сервиса | Гербер (riniran) |
| Администратор | Гербер (riniran) |

## 2. Состав компонентов

| Компонент | Версия | Назначение | Служба systemd | Порт |
|---|---|---|---|---|
| plugNmeet server | 2.5.3 (сборка из исходников) | API, выдача токенов, логика комнат, веб-клиент | plugnmeet | 127.0.0.1:8080 |
| plugNmeet client | 2.5.4 | Веб-интерфейс в браузере (отдаётся сервером) | — | — |
| LiveKit | 1.13.10 | Медиасервер WebRTC (SFU): видео- и аудиопотоки | livekit | 7880 (сигнализация), 7881/TCP, 50000–50100/UDP |
| NATS (JetStream) | 2.10.11 | Обмен сообщениями: чат, события комнат, проверка токенов (auth_callout) | nats | 127.0.0.1:4222, WebSocket 127.0.0.1:8222 |
| MariaDB | 10.11.14 | База данных plugnmeet_v2: комнаты, записи, аналитика | mariadb | 127.0.0.1:3306 |
| Redis | 7.0.15 | Кэш и временные данные сервера | redis-server | 127.0.0.1:6379 |
| nginx | 1.24.0 | Обратный прокси, TLS-терминация, HTTP → HTTPS | nginx | 80, 443 |
| coturn | — | TURN-сервер для клиентов за NAT | coturn | 3478 |
| Samba AD DC | 4.19.5 | Домен gerber.org: учётные записи, DNS, Kerberos, LDAP(S) | samba-ad-dc | 53, 88, 389, 636 и др. |

Схема взаимодействия:

```
Браузер ──HTTPS 443──► nginx ──► plugNmeet 8080 ──► MariaDB, Redis, NATS
                         ├──────► LiveKit 7880 (WebSocket сигнализации)
                         └──────► NATS WebSocket 8222 (чат, события)
Браузер ──UDP 50000–50100 / TCP 7881──► LiveKit (медиапотоки напрямую)
Вход пользователя ──LDAPS 636──► Samba AD (проверка учётной записи и групп)
```

## 5. Зона ответственности администратора

**Входит:**

- серверная ОС srv-1: обновления, учётные записи, параметры ОС, журналы, аудит;
- все компоненты сервиса из раздела 2, их конфигурация и службы systemd;
- TLS-сертификаты сервиса и собственный удостоверяющий центр Gerber Root CA;
- интеграция с доменом: сервисная учётная запись, группы доступа к сервису;
- резервное копирование и проверка восстановления;
- мониторинг, журнал инцидентов, разбор инцидентов (пост-мортем);
- репозиторий конфигурации /opt/plugnmeet-infra;
- клиентский хост WIN-CL1: сценарии копирования резервных копий, параметры ОС и политики.

**Не входит:**

- гипервизор (ноутбук с KVM/libvirt) и сеть libvirt — только по согласованию с владельцем ноутбука;
- доступ в интернет и внешний DNS;
- оборудование и браузеры пользователей (только консультации);
- исходный код plugNmeet и LiveKit — используются официальные версии без изменений.

| Обязательно перед работами | Снимок ВМ и свежая резервная копия; изменение фиксируется в git |

## 7. Требования к безопасности

- Доступ к сервису — только по HTTPS (TLS 1.2/1.3); HTTP перенаправляется на HTTPS.
- Внутренние службы (MariaDB, Redis, NATS, plugNmeet API) слушают только 127.0.0.1, снаружи доступны лишь через nginx.
- Вход пользователей — по доменным учётным записям; права определяются группами домена.
- Секреты (ключи API, пароли БД) не хранятся в git.
- Изменения конфигурации фиксируются в git и подлежат аудиту (auditd).
